# نظام نقاط بيع السوبر ماركت (Codex)

## حالة المشروع: المرحلة 1، 2، 3 + تحسينات إضافية ✅

**المرحلة 1:** هيكلة المشروع + قاعدة البيانات + نظام الموديولات

**المرحلة 2 (المخزون):** إضافة/تعديل صنف، قارئ باركود، تنبيه نقص المخزون

**المرحلة 3 (نقطة البيع):** بحث/باركود، سلة، إتمام بيع، خصم مخزون تلقائي

**موديول جديد — الهوية والصلاحيات (auth):**
- شاشة تسجيل دخول إلزامية قبل أي استخدام
- حساب أدمن افتراضي أول تشغيل: **اسم المستخدم: admin / كلمة السر: admin123** (غيّرها فورًا من إدارة المستخدمين)
- إدارة مستخدمين كاملة (إضافة كاشير جديد، تفعيل/تعطيل حساب) - تظهر بس للأدمن
- كل فاتورة بيع بقت مربوطة فعليًا بمين باعها
- تقرير "مبيعات كل كاشير" في شاشة المحاسبة
- **نظام ورديات (عهدة)**: كل تسجيل دخول بيبدأ وردية بوقت محدد، وعند الخروج بيظهر ملخص فوري (كام فاتورة، كاش، فيزا) قبل قفل الوردية. سجل كامل بكل الورديات متاح للأدمن
- **إقفال اليومية**: أي يوم فات بيتقفل تلقائيًا بمجرد فتح التطبيق في يوم جديد (صورة ثابتة من الأرقام محفوظة للأبد)، بالإضافة لزرار "إقفال يومية اليوم" يدوي للأدمن وقت ما يحب
- **موديول النسخ الاحتياطي**: تصدير نسخة كاملة من قاعدة البيانات ومشاركتها (واتساب/درايف يدويًا)، واستيراد نسخة قديمة لاسترجاع البيانات أو نقلها لجهاز جديد
- **نظام الكمية والوحدة والعبوة الذكي**: كل صنف بقى ليه وحدة قياس (كيلو/جرام/قطعة/لتر أو مخصصة) ونوع عبوة (صندوق/كيس/صفيحة/زجاجة أو مخصص)، والفورم بيحسب الإجمالي الفعلي تلقائيًا سواء العبوة بتحتوي على عدد قطع، أو عبوات داخلية بأوزان/أحجام كسرية (زي أكياس الأرز أو زجاجات الزيت)
- **توليد وطباعة الباركود التلقائي**: أي صنف من غير باركود بيتولّد له كود EAN-13 صحيح رياضيًا تلقائيًا عند الحفظ، وتظهر شاشة فيها الباركود جاهز للطباعة على طابعة ملصقات أو المشاركة كـ PDF
- **موديول الموردين ودفعات التوريد**: سجل موردين كامل (اسم، مندوب، تليفون، عنوان)، وكل توريد لصنف بيتسجل كسطر منفصل (تاريخ التوريد، الصلاحية، المورد، اسم المستلم من المحل) والكمية بتتضاف فوق الموجود من غير ما تستبدله. شاشة بروفايل لكل مورد بتوري كل توريداته، وسجل توريدات لكل صنف مرتب حسب الصلاحية (نظام FIFO) مع تمييز الدفعات القريبة من انتهاء الصلاحية
- **إصلاح**: شاشة "تعديل صنف" بقت بتعرض بطاقة ملخص فوق (آخر مورد، تاريخ آخر توريد، أقرب صلاحية) وبتحدّث الكمية فورًا بعد أي توريد جديد، بدل ما تفضل عارضة بيانات قديمة لحد ما تقفل وتفتح التطبيق تاني
- **تنظيم المخزون بالفئات**: الشاشة الرئيسية للمخزون بقت بتعرض الفئات (زيوت، مكرونة، أرز...) بدل قايمة مسطحة، وتدخل على فئة تلاقي بس أصنافها. إضافة فئة جديدة بضغطة زرار، واختيار الفئة بقى جزء من فورم إضافة الصنف. البحث الشامل في كل الأصناف والباركود لسه متاحين من غير قيد الفئة
- **إصلاح**: شاشة "تعديل صنف" بقت محمية بـ SafeArea عشان الزراير السفلية (تسجيل توريد جديد، سجل التوريدات) متختفيش تحت شريط أزرار الموبايل
- **صور المنتجات**: كل صنف تقدر تضيفله صورة (من الكاميرا أو المعرض)، وبتظهر كصورة مصغّرة في قائمة أصناف كل فئة
- **تفاصيل الوردية الكاملة**: بعد ما تقفل الوردية، الأرقام (كاش، فيزا، عدد فواتير) بتتحفظ بشكل دائم مش بس تعرض لحظي. الأدمن يقدر يدخل على أي وردية قديمة من السجل يشوف كل الفواتير اللي اتباعت فيها بالتفصيل، ويأكد إنه استلم العهدة فعليًا بزرار "تأكيد الاستلام" - والوردية اللي لسه ما اتأكدتش بتظهر بعلامة تحذير في السجل
- **إعدادات المحل**: اسم، لوجو، تليفون، عنوان (زرار الإعدادات ⚙️ في الشاشة الرئيسية)
- **بيانات العميل**: اسم ورقم تليفون اختياريين لكل فاتورة
- **شاشة فاتورة تفصيلية**: تظهر تلقائيًا بعد كل عملية بيع، وبتتفتح من سجل المبيعات القديمة كمان، وشكلها جاهز للتصوير أو الطباعة
- **موديول المحاسبة الفعلي**: إيرادات وأرباح اليوم والشهر، تسجيل مصروفات، صافي الربح

## طريقة التشغيل
1. تأكد إن Flutter SDK مثبت على جهازك (`flutter --version`)
2. من داخل مجلد المشروع:
   ```
   flutter pub get
   flutter run
   ```

## هيكل المشروع
```
lib/
  core/                      حاجات مشتركة بين كل الموديولات
    database/                قاعدة البيانات المحلية (SQLite)
    modules_registry/        نظام تفعيل/تعطيل الموديولات
    networking/               🔜 المرحلة 5 - السيرفر المحلي
    backup/                   🔜 المرحلة 6 - النسخ الاحتياطي
    printing/                 🔜 المرحلة 4 - طباعة الباركود
    licensing/                🔜 المرحلة 8 - نظام الترخيص
  modules/
    inventory/                🔜 المرحلة 2
    sales/                    🔜 المرحلة 3
    accounting/                🔜 المرحلة 7
```

## الجداول الموجودة في قاعدة البيانات

settings, modules, licensed_modules, modules_settings

## إضافة موديول جديد بعدين (زي CRM أو HR)
1. اعمل مجلد جديد في `lib/modules/` بنفس نمط `inventory/`
2. أضف تعريف الموديول في `lib/core/modules_registry/module_registry.dart`
3. أضف صف للموديول في جدول `modules` بقاعدة البيانات
